> 第 3 部分。上一篇：[02-方案选型与语言论证.md](02-方案选型与语言论证.md)；下一篇：[04-Go 工程分层与规范.md](04-Go%20工程分层与规范.md)

## 1. 总体架构

MeowFlixEmby 是运行在**播放器所在客户端机器**上的 Go 常驻守护进程。它通过 WebSocket 把自己注册成 Emby 的一个"可遥控/可投放会话"，接收服务器下发的播放与遥控指令，按资源类型选择最佳播放方式拉起本地播放器，并把进度回传给服务器。

```
┌────────────┐         浏览器点"Play On/投放"选中本机
│  浏览器     │ ──────────────────────────────────────┐
│ (Emby web) │                                        │
└────────────┘                                        ▼
                                            ┌────────────────────┐
┌────────────────────┐   ①认证 REST        │    Emby / Jellyfin   │
│                     │◄───────────────────│      服务器          │
│   MeowFlixEmby      │   ②WebSocket 长连接 │  (可异地/NAS/云)     │
│   (Go 守护进程)      │◄══════════════════►│                    │
│                     │   ③收 Play/Playstate└────────────────────┘
│  ┌───────────────┐  │   ④REST 拿 PlaybackInfo / 回传进度
│  │ remote 会话   │  │
│  ├───────────────┤  │            ⑤按资源类型决策
│  │ resolver 决策 │──┼──► 直连网盘URL / 本地磁盘路径 / HTTP串流
│  ├───────────────┤  │
│  │ player 驱动   │──┼──► 本地播放器 (mpv/pot/vlc/mpc...)
│  ├───────────────┤  │         ▲ IPC 读进度、控暂停/快进/切集
│  │ progress 回传 │  │         │
│  └───────────────┘  │◄────────┘
└────────────────────┘
```

## 2. 运行时序

### 2.1 启动与注册（成为投放目标）

1. **认证**：`POST {base}/Users/AuthenticateByName`，body `{"Username":..,"Pw":..}`，请求头
   `Authorization: Emby UserId="", Client="MeowFlix", Device="<主机名>", DeviceId="<持久GUID>", Version="<ver>", Token=""`。
   取响应 `AccessToken`、`User.Id`。**DeviceId 必须持久化**，且认证、WebSocket、能力声明三处一致。
   > API Key 方式不适用：admin API key 不绑定用户，不会成为可控投放目标。必须以真实用户认证。
2. **声明能力**：`POST {base}/Sessions/Capabilities/Full`（带 `X-Emby-Token`），body：
   ```json
   {
     "PlayableMediaTypes": ["Video","Audio"],
     "SupportedCommands": ["PlayPause","Pause","Unpause","Stop","Seek","NextTrack","PreviousTrack","SetSubtitleStreamIndex","SetAudioStreamIndex","DisplayMessage","SetVolume","Mute","Unmute"],
     "SupportsMediaControl": true,
     "SupportsPersistentIdentifier": true
   }
   ```
   `SupportsMediaControl:true` 是让本机出现在"Play On"菜单的关键开关。`SupportedCommands` 只声明实际实现的子集；完整可用集随服务器版本变化，运行时从服务器枚举，不硬编码 **[待联调核实]**。
3. **建立 WebSocket**：由 HTTP base URL 做 scheme 替换（`https→wss`、保留路径前缀）得到
   `ws(s)://host[/emby]/embywebsocket?api_key=<AccessToken>&deviceId=<DeviceId>`。
   > Jellyfin 路径为 `/socket`（**[待联调核实]**，以 jellyfin-apiclient-python 为准），认证头 scheme 关键字用 `MediaBrowser`。适配层按 `server.type` 切换。
4. **保活**：服务器周期发 `KeepAlive`/`ForceKeepAlive`，回 `{"MessageType":"KeepAlive"}`。**会话空闲超时（约 5 分钟无活动/断连即从投放列表消失）**，因此必须维持心跳，断线重连后**重新 POST 能力**。

### 2.2 收到投放 → 播放

WebSocket 消息统一信封：`{"MessageType":<name>,"Data":<obj|string>,"MessageId":<opt>}`。

收到 `Play`：
```json
{ "MessageType":"Play",
  "Data":{ "ItemIds":["<id>"], "PlayCommand":"PlayNow",
           "StartPositionTicks":0, "StartIndex":0, "ControllingUserId":"<uid>" } }
```
- `PlayCommand` ∈ `PlayNow|PlayNext|PlayLast`。`ItemIds` 为队列，播首个、其余作连播。
- `StartPositionTicks` 为续播起点（100ns tick）**[待联调核实是否 0 时省略]**。

处理流程：
1. 对首个 ItemId 调 `POST {base}/Items/{id}/PlaybackInfo`（body 可带 `UserId`、`StartTimeTicks`、`DeviceProfile`、`MaxStreamingBitrate`），拿 `MediaSources[]` 与 `PlaySessionId`（**全程复用同一 PlaySessionId** 串联流地址与进度回传）。
2. 送入 **resolver 决策引擎**（见 §3）选出播放方式与最终 media path/url。
3. 需要元数据（标题/剧集/续播位）时调 `GET {base}/Users/{uid}/Items/{itemId}`。
4. **player 驱动**拉起本地播放器（见 §4），传入 media path、起播秒、字幕、标题。

### 2.3 遥控指令

`Playstate`：
```json
{ "MessageType":"Playstate",
  "Data":{ "Command":"Seek", "SeekPositionTicks":6000000000, "ControllingUserId":"<uid>" } }
```
`Command` ∈ `Stop|Pause|Unpause|PlayPause|NextTrack|PreviousTrack|Seek|Rewind|FastForward|SeekRelative`。映射到播放器 IPC 控制。`SeekPositionTicks` 为绝对目标位（100ns）。

`GeneralCommand`（音量/字幕/消息）：`Data.Name` 为 `GeneralCommandType`，`Data.Arguments` 为字符串 map（如 `DisplayMessage` → `Header/Text/TimeoutMs`；`SetVolume` → `Volume`）。

### 2.4 进度回传

三个 REST 端点（带 `X-Emby-Token`），body 为 `PlaybackStart/Progress/StopInfo`：
- 开始：`POST {base}/Sessions/Playing`
- 进度：`POST {base}/Sessions/Playing/Progress`（周期 ~1–10s + 状态变化时）
- 停止：`POST {base}/Sessions/Playing/Stopped`（送最终位置）

```json
{ "ItemId":"<id>", "PlaySessionId":"<psid>", "MediaSourceId":"<msid>",
  "PositionTicks":10460000000, "IsPaused":false, "CanSeek":true,
  "PlayMethod":"DirectStream", "AudioStreamIndex":1, "SubtitleStreamIndex":-1,
  "RepeatMode":"RepeatNone" }
```
- **PositionTicks 单位 = 100ns，即 秒 × 10,000,000**。`StartPositionTicks`/`SeekPositionTicks`/`RunTimeTicks` 同单位。
- `PlayMethod` ∈ `DirectPlay|DirectStream|Transcode`：直连磁盘用 `DirectPlay`，HTTP 串流用 `DirectStream`。

## 3. 播放方式决策引擎（resolver — 本项目核心价值）

复刻并简化参考项目 `data_parser.py` 的判定，输入 `MediaSource`（`Path`/`Protocol`/`Container`/`DirectStreamUrl`/`TranscodingUrl`/`IsRemote`）+ 本地配置，输出 `Decision{Method, MediaPathOrURL, PlayMethod}`。

判定优先级（自上而下，命中即止）：

| 序 | 条件 | 方式 `Method` | media | 回传 `PlayMethod` |
|---|------|------|------|------|
| 1 | `MediaSource.Path` 前缀命中 `force_disk_prefixes` | `DirectDisk` | `pathmap(Path)` | DirectPlay |
| 2 | strm/`Protocol=Http` 源 且 host 命中 `direct_url_hosts`（网盘直连） | `DirectURL` | 源 http 地址 | DirectStream |
| 3 | 配置了 `path_maps` 且 `pathmap(Path)` 命中前缀（本地已挂载 NAS） | `DirectDisk` | `pathmap(Path)` | DirectPlay |
| 4 | 其余 | `HTTPStream` | `base + DirectStreamUrl`（或 `/Videos/{id}/stream?Static=true&MediaSourceId=..&PlaySessionId=..&api_key=..`）；服务器要求转码则用 `TranscodingUrl`(HLS) | DirectStream/Transcode |

配套子模块：
- **pathmap**（`resolver/pathmap.go`）：`src`→`dst` 前缀替换 + 路径分隔符归一 + 可选 `path_check`（文件存在 + NFC/NFD 规范化）。对应 `translate_path_by_ini`。
- **version**（`resolver/version.go`）：多 `MediaSource` 时按 `version.prefer` 关键字优选。对应 `version_prefer_emby`。
- **subtitle**（`resolver/subtitle.go`）：按 `subtitle.priority` 关键字挑外挂/内封字幕；HTTP 串流下外挂字幕生成 `/Videos/{id}/{msid}/Subtitles/{idx}/Stream.{codec}?api_key=..`。对应 `subtitle_checker`。

> 决策引擎为纯函数、无 I/O（`path_check` 除外），是单元测试重点（表驱动覆盖四条路径 + strm 多版本边界）。

## 4. 播放器驱动（player）

对每种播放器实现 `Player`/`Handle` 接口（见 [04](04-Go%20工程分层与规范.md) §3）：

| 播放器 | 进度/控制通道 | 起播参数 | 遥控支持 |
|------|------|------|------|
| **mpv / mpv.net / IINA** | JSON IPC：Windows 命名管道 `\\.\pipe\<name>`，Unix `/tmp/<name>.sock`（`--input-ipc-server`） | `--start=`、`--sub-file=`、`--force-media-title=` | ✅ 全（pause/seek/切集/播放列表） |
| **VLC** | HTTP 接口 `:port/requests/status.xml`（`--http-port`、`--http-password`） | `:start-time=`、`--sub-file` | ✅ 大部分 |
| **PotPlayer** | 命令行 + 窗口消息 | `/seek=`、`/sub=`、`/title=` | ⚠️ 有限（进度回传偏弱） |
| **MPC-HC/BE** | Web 接口 `/variables.html`、`/command.html` | `/start ms`、`/sub` | ⚠️ 部分 |
| **generic** | 仅 `os/exec` 拉起 | 尽力传参 | ❌ 不回传 |

- 进度轮询：`Handle.Progress()` 周期读 `(posSec, durSec)`，喂给 progress 回传与连播判定。
- 连播：mpv 走原生 playlist；不支持的播放器按"进度>0.9 关闭→拉起下一集"降级（对应参考项目 `http_sub_auto_next_ep`）。
- 单实例/多开：配置 `one_instance` 控制。
- 播放器选择：`players.default` + `players.by_path`（按路径关键字/bdmv/iso 切换），对应 `select_player_by_path`。

## 5. 可插拔集成的三种形态

1. **Go 库**：`import github.com/<org>/MeowFlixEmby/pkg/...`，用 `playback.NewController(server, resolver, playerRegistry, reporter)` 装配。
2. **进程内接口注入**：第三方实现 `mediaserver.Server` / `player.Player` / `resolver.Resolver` 注入自定义后端或播放器。
3. **跨语言 FFI**：`go build -buildmode=c-shared -o meowflix.dll ./api/ffi`，导出 `Start/Stop/OnEvent` 供 C/Python/.NET 调用；事件用 JSON schema（`api/` 下）。
4. **独立运行**：`cmd/meowflix` 单文件二进制 + 配置 + 自启脚本。

## 6. 安全考量

- **凭据**：`AccessToken`、密码不落日志（`log.mask_sensitive`，对应 `mix_log`）；配置文件建议 0600 权限；支持 `api_key` 直填避免存密码。
- **本地无监听端口**：A 方案下本机作为 WebSocket **客户端**，默认不开监听端口，攻击面小于参考项目的本地 HTTP 服务。若后续需要本地控制接口，仅监听 `127.0.0.1` 并加 token。
- **TLS**：默认校验服务器证书；自签名场景提供显式 `skip_verify` 开关（默认关，对应 `skip_certificate_verify`）。
- **播放器子进程**：命令行参数经转义构造，避免注入。

## 7. 与 Jellyfin / Plex 的差异（适配层封装）

| 项 | Emby | Jellyfin | Plex |
|---|------|------|------|
| 认证 header scheme | `Emby` | `MediaBrowser`（兼容 `Emby`） | `X-Plex-Token` |
| WebSocket 路径 | `/embywebsocket` | `/socket` **[待核实]** | 无（Companion/GDM） |
| 能力/指令/进度 | 见上 | 基本一致（同 wire name） | 完全不同：`/player/playback/*` + `/:/timeline` |

Plex 机制与 Emby 差异大（HTTP 命令 + header 定向，非 WS 推送），列为**可选后续适配**，接口层预留 `plex` 实现位。
